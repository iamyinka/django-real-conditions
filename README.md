# Django Under Real Conditions

The companion repository for a practical video course. You build five Django business applications from an empty folder all the way to deployment. Docker, Docker Compose, and a professional Git workflow run through every project.

| Project | Directory | Focus | Status |
|---|---|---|---|
| Telecom operations & field service | `projects/telecom/` | Permissions, idempotency, outbox notifications, offline sync | In progress |
| Telehealth consultations | `projects/telehealth/` | Access boundaries, sessions, signed URLs, reminders, WebRTC via LiveKit | Planned |
| Streaming & offline learning | `projects/streaming/` | Multipart uploads, FFmpeg, HLS, offline downloads | Planned |
| Lab logistics & live tracking | `projects/labtrack/` | State machines, custody events, WebSockets, geolocation | Planned |
| Private intranet over LAN & OpenVPN | `projects/intranet/` | Networking, internal DNS/HTTPS, VPN lifecycle | Planned |

Each project is an **independent Django project** with its own dependencies, Compose file, migrations, sample data, and deployment guide. Shared code is kept deliberately small, and the reason for each shared piece is documented.

## How to read this repository honestly

Everything here is labeled:

| Label | Meaning |
|---|---|
| **Tested** | Run, with the command, platform, and result recorded in `VERIFICATION_MANIFEST.md`. |
| **Prepared-only** | Configuration or instructions that have not been run against real infrastructure. |
| **Simulated** | A stand-in for a real external system: SMS providers, carriers, clinical data, laboratory results, reviewers. |
| **Hypothesis** | A performance or success target that hasn't been measured yet. |

All data is synthetic. Nothing here is a clinically deployable system or a regulated laboratory system, and none of it makes a compliance claim.

## Layout

```
projects/<app>/      one independently runnable Django project per application
course/              lesson scripts, storyboards, notes, exercises, style guide
docs/                cross-project guides (Git workflow, conventions)
.github/             issue/PR templates and CI workflows
```

## Git workflow (summary)

- `main` is protected. Every change goes through a short-lived branch and a pull request, then a squash merge.
- Branch names: `feat/…`, `fix/…`, `chore/…`, `docs/…`, `hotfix/…`.
- Lesson checkpoints use tags like `lesson/M01.05-end`. Solutions use tags like `solution/M01.05`.
- Releases are tagged separately for each project, like `telecom/v1.0.0`.
- Reverting code **does not** undo database migrations.

The full workflow is in `docs/GIT_WORKFLOW.md`.

## Never committed

Secrets, `.env` files, uploaded media, database files, local virtual environments, or rendered video and audio. Sample data is always generated by a reproducible command.
