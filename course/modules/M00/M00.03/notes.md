## What "independent" means for each project

| Owned by each project | Why |
|---|---|
| `pyproject.toml` + `uv.lock` | Each project upgrades dependencies on its own schedule |
| `Dockerfile` + `compose.yaml` | Each runs its own containers, network and volumes. The Compose project name (`name: telecom`) keeps container and volume names separate. |
| `.env.example` | Each documents its own settings |
| Release tags `<project>/vX.Y.Z` | Each ships on its own |

## Commands

### `git check-ignore -v <path>`
- **Where it runs:** host, repository root

| Part | Meaning |
|---|---|
| `git check-ignore` | Asks whether a path is ignored |
| `-v` | Verbose: print the source file, line number and pattern that decided |
| `<path>` | The file to test. It doesn't need to exist. |

- **Expected output** for `projects/telecom/.env`: `.gitignore:2:.env	projects/telecom/.env` (file, line, pattern, path).
- For `projects/telecom/.env.example`: **no output, exit status 1.** The file is tracked, and ignore rules never apply to tracked files. Verified on Git 2.50.1.
- `git check-ignore -v --no-index projects/telecom/.env.example` tests the rules alone and prints `.gitignore:4:!.env.example	projects/telecom/.env.example`. The leading `!` marks a negation: this rule *un-ignores* the file. The exit status is 0, because a rule matched, even though the result is "not ignored".
- **Exit status:** 0 if a rule matched, 1 if nothing matched (or the path is tracked, without `--no-index`).

### `uvx pre-commit run gitleaks --files <path>`

| Part | Meaning |
|---|---|
| `uvx` | Runs a Python tool in a temporary environment without installing it into your project |
| `pre-commit` | The hook runner configured by `.pre-commit-config.yaml` |
| `run gitleaks` | Run only the hook with id `gitleaks` |
| `--files <path>` | Check these files instead of only staged changes |

- **Expected output (failure):** `Detect hardcoded secrets....Failed`, then `RuleID: github-pat`, `File:`, `Line:`. The secret itself is shown as `REDACTED`.
- **Normal use:** after `uvx pre-commit install`, the hooks run automatically on `git commit`, and a failure stops the commit.

## Code

### `.gitignore` (key rules)

| Rule | Ignores | Why |
|---|---|---|
| `.env`, `.env.*` | Local settings files with real values | Secrets |
| `!.env.example` | *Un-ignores* the committed template | The `!` negates an earlier match. Order matters: the negation must come after the rule it overrides. |
| `*.pem`, `*.key`, `*.p12`, `*.ovpn`, `pki/`, `secrets/` | Keys, certificates, VPN profiles | Module 11 creates all of these |
| `.venv/`, `__pycache__/`, `*.py[cod]` | Virtual environments, bytecode | Large, machine-specific, regenerated by `uv sync` |
| `*.sqlite3`, `media/`, `staticfiles/`, `backups/` | Databases, uploads, build output, dumps | Data, not source |
| `*.mp4`, `*.wav`, … | Rendered course media | Huge binaries |

### `.gitattributes`

| Line | Meaning |
|---|---|
| `* text=auto eol=lf` | Git detects text files and checks them out with LF line endings on every OS |
| `*.sh text eol=lf` | Always LF for shell scripts. A CRLF script fails in Linux with `/bin/sh^M: bad interpreter`. |
| `*.png binary` | Never convert or diff these |

### `.pre-commit-config.yaml` (hooks)

| Hook | Catches |
|---|---|
| `trailing-whitespace`, `end-of-file-fixer` | Noise in diffs |
| `check-yaml`, `check-toml` | Broken config files |
| `check-merge-conflict` | Leftover `<<<<<<<` markers |
| `check-added-large-files` | Accidentally committed binaries |
| `detect-private-key` | PEM private keys |
| `ruff-check`, `ruff-format` | Python lint and formatting |
| `gitleaks` | Tokens, keys and passwords by pattern and entropy |

## Tradeoffs and alternatives
- **Monorepo vs. one repository per project:** separate repositories give stronger isolation and simpler permissions; a monorepo gives one history and cross-project PRs. Independence *inside* the monorepo gets most of the isolation anyway.
- **Pre-commit hooks can be skipped** (`git commit --no-verify`). That's why the same checks run in CI.

## Troubleshooting

| Symptom | Cause | Fix |
|---|---|---|
| A file you expected to be ignored shows in `git status` | It was committed before the rule was added. Ignore rules don't apply to tracked files. | `git rm --cached <file>`, commit, and rotate any secret it contained |
| gitleaks flags a harmless test value | A false positive | Prefer an obviously fake value. If you must keep it, add a `# gitleaks:allow` comment on that line and explain why in the PR. |
| `pre-commit: command not found` | It isn't installed globally | Use `uvx pre-commit …` as the course does |
